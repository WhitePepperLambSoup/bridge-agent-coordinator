# Agent 档案、路由与成本优化

## 动态 Agent 档案

Agent 不使用固定 A/B/C 字段。每个档案包含：

- 唯一 ID、显示名、provider、model；
- capability tier 与 cost tier；
- roles、strengths、weaknesses；
- 可规划、编辑、审查、批准和合并权限；
- 最大并行任务、上下文预算和重试预算；
- 工作区模式；
- 用户路由覆盖；
- 本地历史成功指标。

模型注册表只提供建议，用户配置优先。

## 硬过滤

候选 Agent 必须满足：

- 具有任务所需角色和权限；
- 支持语言、工具和工作区模式；
- 未超过并行任务数；
- 风险等级在允许范围；
- 预算可用；
- 可以取得文件/全局资源租约；
- 没有被禁用或处于异常工作区。

硬过滤失败的 Agent 不参与评分。

## 可解释评分

```text
score =
  capability_match * 0.35
  + historical_success * 0.20
  + specialty_match * 0.15
  + availability * 0.10
  + context_fit * 0.10
  + cost_efficiency * 0.10
  - failure_penalty
  - escalation_risk
```

权重按风险调整：Low 提高成本效率，High/Critical 提高能力与历史成功率。Bridge 必须显示推荐原因和被排除原因，用户可覆盖，覆盖写入事件。

## 强模型边界

默认分配给强模型：

- 目标澄清、架构、公共接口；
- 安全、数据一致性和跨模块难点；
- 两轮低成本修复仍失败的问题；
- 独立审查、最终验收；
- 只读诊断和决策。

默认不分配给强模型：

- CRUD、样板测试、批量重命名；
- 格式和 lint 修复；
- 普通依赖升级；
- 已有明确设计的实现；
- 文档搬运和第一轮普通 bug 修复。

## 分层上下文

| 层 | 内容 | 失效条件 |
|---|---|---|
| 项目层 | 技术栈、架构、全局约束 | 全局架构决定变化 |
| 模块层 | 接口、关键文件、已知陷阱 | 相关路径或接口变化 |
| 任务层 | 目标、范围、验收、检查 | task version 变化 |
| 增量层 | diff、失败日志、审查意见 | attempt 变化 |

上下文使用 source commit 和内容哈希。相关路径未变时复用摘要；无关目录变化不使摘要失效。

## 审查包

强模型审查只接收：

1. 任务目标和风险；
2. 已批准决定；
3. 验收标准；
4. 修改文件清单；
5. 基线到候选提交的 diff；
6. 独立检查证据；
7. 实现 Agent 回执；
8. 已知风险和待确认问题。

不得默认附带完整聊天历史或整个仓库。

## 升级包

升级包必须包含最小问题、期望、失败证据、尝试历史、相关 diff、相关上下文和需要强模型做出的明确决定。强模型优先提供方案，方案再交给低成本 Agent 实施。

## 预算守卫

支持项目、任务和 Agent 三层：

- 最大估算费用；
- 最大输入/输出 token；
- 最大尝试轮次；
- 最大强模型调用次数；
- 最大无进展次数；
- 每日和项目预算。

50% 提醒，80% 暂停自动升级，100% 暂停新调用并请求用户决策。真实数据和估算数据必须明确区分。

## 历史反馈

可记录任务类型成功率、平均修复轮次、越界次数、审查驳回率、完成时间和单位成功任务成本。历史数据只影响建议，不自动剥夺用户选择。

## 成本节省报告

报告可以展示“如果全部由强模型完成”的估算对比，但必须公开模型、token 和价格假设，不得将估算宣传为精确节省。
