# 11. 完整测试与验收规范

## 1. 验收原则

“程序能启动”不等于桥接成立。发布验收必须证明：不同 Agent 能在隔离工作区中领取正确任务，低成本 Agent 完成主要实现，强模型进行规划、疑难升级和最终审查，协调器能防止越权覆盖、错误推进和不可恢复的 Git 操作。

所有关键结论都要有可重复运行的测试或保存的验收证据。

## 2. 单元测试

覆盖：

- 状态机的每个合法与非法迁移
- 依赖解析、路由评分和升级规则
- 路径规范化、允许/禁止范围与符号链接边界
- 租约获取、续约、到期、撤销和所有者检查
- 配置合并、版本检查和硬安全底线
- manifest、receipt、artifacts 的 schema 与交叉字段校验
- token、时间、重试和费用预算
- 三种确认策略及单项覆盖规则
- Markdown 生成和事件序列

## 3. 协议金样与反例

至少提供以下固定 fixtures：

- 合法 `COMPLETED` 回执
- 合法 `BLOCKED` 回执
- 错误 task ID、attempt ID 或 lease token
- 过期 attempt 的回执
- 重复回执
- 缺失验证证据
- 被修改的任务 manifest
- 不支持的协议版本
- 声称完成但存在禁止路径改动

每个反例必须断言：数据库未错误推进、错误代码正确、用户可以看到恢复建议。

## 4. 数据库与恢复测试

- 新库初始化与默认值
- 每个版本迁移、迁移回滚和备份恢复
- 乐观并发版本冲突
- 状态与事件的事务一致性
- 写入中崩溃、磁盘空间不足和数据库损坏模拟
- 旧锁、活锁、只读第二实例和显式接管
- 高版本数据库拒绝写入

## 5. 真实 Git 集成矩阵

测试必须使用临时真实 Git 仓库，而不是只 mock 命令：

- 普通仓库与 worktree 中 `.git` 为文件的情况
- 无 remote、detached HEAD、已有脏改动、未跟踪文件
- 基线过期、目标分支前进
- 两个 Agent 并行修改不同文件
- 两个 Agent 修改同一文件形成冲突
- cherry-pick 成功、冲突、中断和恢复
- 允许/禁止文件范围检查
- 符号链接逃逸、大小写差异和 Windows 路径
- revert 成功与失败
- 安全清理、Agent 丢失、租约过期后接管

任何清理测试都必须先验证目标在测试临时目录内。

## 6. 文件监听测试

- 分块/慢速写入，不能读取半个文件
- 临时文件写完后原子替换
- 同一变化产生多次通知
- 稳定窗口判断
- 程序重启后补扫未导入回执
- UTF-8、换行差异、超大文件和权限错误
- 文件被编辑器短暂占用

## 7. 验证执行器测试

- 成功、非零退出码、超时和用户取消
- 超大 stdout/stderr 截断
- 子进程树清理，不遗留孤儿进程
- 含空格路径和参数
- 禁止 shell 注入
- 必需证据存在、缺失或哈希不一致

## 8. GUI 端到端测试

完整流程：

1. 创建或打开项目。
2. 配置 Codex、Reasonix 和第三个通用 Agent。
3. 由强模型生成计划并由用户批准。
4. 低成本 Agent 领取实现任务。
5. 导入回执并自动验证。
6. 失败后生成修复任务；达到阈值后升级给强模型。
7. 强模型审查，要求修改，再批准。
8. 合并队列完成集成并生成验收报告。
9. 重启程序，状态与证据完整恢复。

还要覆盖：手动、半自动、自动三种推进方式；Strict、Balanced、Expert 三种确认模式；中英文界面；任务取消、暂停、重新派发和崩溃恢复。

## 9. 安全专项测试

- Agent 试图修改禁止路径
- 回执伪造另一个任务或 Agent 身份
- manifest 被编辑后继续提交
- 绕过租约直接写入共享工作区
- 危险命令在三种策略下的确认行为
- 用户配置试图关闭硬安全底线
- worktree 删除目标被路径穿越替换
- 日志和诊断包不泄露秘密与环境变量

## 10. Markdown 与文档 QA

生成一份自动化 QA 表，至少检查：

| 检查项 | 通过条件 |
|---|---|
| 相对链接 | 目标文件存在 |
| 模式引用 | 配置中存在相应枚举 |
| 模板语言 | 英文模板不混入中文固定文案 |
| 敏感信息 | 不含 key、token 或本机秘密路径 |
| Agent 数量 | UI 与协议不写死为两个 |
| 所有权 | 每个进行中任务有有效租约 |
| 生成视图 | 可从 SQLite 重建 |
| Schema 一致性 | 示例与实现 schema 同步 |

## 11. 性能基线

在参考开发机上：

- 1,000 个任务的常用 UI 查询小于 200 ms。
- 10,000 个事件的正常启动小于 3 秒。
- 文件稳定后 1 秒内发现回执。
- 单个任务包生成小于 500 ms。
- 不把所有历史完整 diff 常驻内存。
- 验证输出有上限，GUI 主线程不执行阻塞 I/O。

指标需记录测试机器与数据规模，不能把参考值当作所有设备的绝对保证。

## 12. 发布门禁

发布前全部满足：

- 无未解决 P0/P1 缺陷。
- 数据库迁移和崩溃恢复测试通过。
- 真实两 Agent 完整流程通过。
- 三 Agent 并行流程通过。
- Git 冲突、修复、审查与回滚流程通过。
- “低成本 Agent 失败 → 强模型诊断 → 低成本 Agent 修复”流程通过。
- 所有推进模式、安全模式、语言和关键恢复场景通过。
- 安装、升级、卸载不删除用户仓库或工作成果。

验收报告必须列出版本、提交、环境、执行命令、通过/失败数、已知限制和证据路径。
