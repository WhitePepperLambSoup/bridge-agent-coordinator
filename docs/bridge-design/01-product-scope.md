# 产品边界与成功标准

## 产品目标

Bridge 帮助用户协调多个手动打开的本地 Agent，将任务交给成本和能力最匹配的模型，并通过结构化任务包、回执、验证、Git worktree 和合并队列实现可靠协作。

最重要的成本目标是减少强模型重复读取项目、机械编码和多轮低价值修复所消耗的 token。强模型应集中处理：

- 需求澄清与规划；
- 架构和公共接口；
- 高风险决策；
- 低成本 Agent 连续失败后的难点；
- 独立审查与最终验收。

低成本 Agent 应集中处理：

- 已有明确设计的实现；
- 测试编写和回归；
- 批量或机械修改；
- 普通 bug 修复；
- 文档和维护任务。

## 产品不做什么

首版不包含：

- 自动点击或控制 Codex、Reasonix 桌面窗口；
- 自动调用模型 API；
- 保存模型 API Key；
- 云端账号、多用户服务端和移动端；
- 非 Git 版本控制；
- 自动 force push、`git reset --hard` 或共享历史重写；
- 从任意自然语言生成并静默执行系统命令；
- 在无法取得真实 token 数据时声称精确成本。

## 用户与角色

### 用户

- 初始化项目和安全策略；
- 配置 Agent 档案；
- 手动把提示词交给 Agent；
- 审批规划、高风险操作、强模型升级和最终验收；
- 在异常恢复时做最终判断。

### 规划/审查 Agent

通常由 Codex 或其他强模型承担，默认采用只读咨询工作区。它可以产出计划、架构决策、审查结论和升级诊断，但默认不直接承担大量编码。

### 实现 Agent

通常由 Reasonix 或其他经济模型承担，在独立 worktree 中执行明确任务，运行检查、提交代码并写回结构化回执。

### Bridge

Bridge 只负责协调、验证和记录，不能把 Agent 的自我声明当作事实。

## 工作区模式

| 模式 | 适用场景 | 并发限制 |
|---|---|---|
| 独立 worktree | 默认开发模式 | 允许不重叠任务并行 |
| 共享目录 | 小型或串行任务 | 同一时间只允许一个写任务 |
| 只读咨询 | 规划、诊断、审查 | 不允许修改代码 |

## 推进策略

- Manual：关键状态均需用户确认。
- Automatic：门禁满足后自动推进，遇到风险或矛盾暂停。
- Hybrid：低风险工作自动，高风险、强模型调用和最终验收人工确认。

项目设置默认 Hybrid，每个任务可覆盖。

## 首版支持矩阵

- Windows 10/11；
- NTFS；
- Python 3.11+；
- Git 2.40+；
- SQLite 标准库；
- Codex、Reasonix、Generic File Agent、Custom Template 手动适配器；
- 动态 Agent 集合，建议 2～8 个。

## 产品级成功标准

首版必须完成以下真实验收：

1. 两个真实 Agent 完成一次规划、实现、审查、修复、合并闭环。
2. 三个 Agent 完成一次无文件范围重叠的并行协作。
3. 制造并安全处理一次 Git 冲突，不损坏主工作区。
4. 完成一次低成本 Agent 两轮失败、升级强模型、再交回低成本 Agent 的闭环。
5. Strict、Balanced、Expert 三种安全策略通过测试。
6. 中文和英文完整生成矩阵无错误引用、无翻译键泄漏、无意外混语。
7. 在合并、回执导入和验证期间强制终止程序后能够恢复。
8. 安装、升级、卸载和清理均不删除用户项目数据。

## 质量底线

- 无 P0/P1 缺陷方可发布。
- Agent 不能越权修改任务范围。
- Agent 不能直接推进数据库状态。
- Agent 不能直接写其他 Agent 的任务包或回执。
- 用户已有文件不得被静默覆盖。
- 无证据的验收项不得自动通过。
