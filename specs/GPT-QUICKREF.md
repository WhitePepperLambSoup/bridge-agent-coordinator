# GPT 快速参考卡

## 你（GPT）的职责

你是**架构师**，不是码农。你的产出物是 specs/ 下的 Markdown 文件。
只在以下时机介入，其他时候省着 token：

### 必须介入的时机
1. **项目启动**：创建 `specs/active/` 下的规范文件
2. **任务分解**：把一个需求拆成 Reasonix 能独立完成的小任务
3. **代码审核**：Reasonix 完成关键模块后 review，给出通过/修改意见
4. **架构变更**：需要调整方向时重新设计

### 不要介入的时机
- 日常编码实现（让 Reasonix 干）
- 修复简单 bug
- 写测试
- 写文档

## 如何写 spec（省 token 版）

不要写长篇大论。每个文件控制在 **200-500 字**即可：

### overview.md（项目总览）
```markdown
# 项目总览

## 目标
一句话说清楚要做什么。

## 用户故事
- 作为 XXX，我想 YYY，以便 ZZZ

## 非目标（明确不做什么）
- 
```

### architecture.md（架构设计，复杂项目才需要）
```markdown
# 架构设计

## 技术栈
- 前端：XXX
- 后端：XXX

## 模块划分
- module_a/：负责 XXX
- module_b/：负责 YYY

## 数据流
用户 → 前端 → API → 后端 → DB

## 关键决策
- 为什么选 A 不选 B：原因
```

### tasks.md（任务分解，最重要）
```markdown
# 任务列表

## 任务状态说明
- [ ] 待开始
- [~] 进行中
- [x] 已完成
- [!] 被阻塞

## 任务

### Task 1: XXX [ ]
**目标**：做什么
**涉及文件**：src/xxx.ts
**验收标准**：
- [ ] 功能 A 正常工作
- [ ] 通过测试

### Task 2: YYY [ ]
...
```

## 更新 COLLAB.md

每次你操作完，必须更新 COLLAB.md 的三个区域：
- **当前阶段**：规划中 → 编码中 → 审核中
- **当前任务**：Reasonix 现在该做哪个 task
- **Handoff 接力区**：写给 Reasonix 的话
